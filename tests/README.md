# CleanFeed tests (dev-only, never added to package.sh)

**Unit** (pure logic, no browser, zero dependencies): `node tests/run-unit.js [name-filter]`
Add `tests/unit/<name>.test.js`: `const test = require('./registry')`, `node:assert`, and
`require('./load-content-dom')()` for content-dom.js bindings (`matchesKeyword`, `YT`, ...). Wrap vm values in `loadContentDom.plain(x)` before `deepStrictEqual`.
For page-level `YT` helpers, build a stub page with `tests/unit/fake-dom.js` (`el()`, `fakeDocument()`; small CSS subset, unsupported selectors throw) and pass it as `loadContentDom({ document, location: { pathname } })`.
For background/storage logic, `require('./load-background')(initialStorage)` vm-loads features.js + storage.js + background.js with an in-memory `chrome.storage.local` and a stub ExtPay: call `handleMessage({ action, ... })`, read `storage()` (plain copy) and `writes` (keys of each `set()`); run `listeners.onInstalled[0](details)` etc. and read `alarmCalls`. Pro status: options `{ isPro, getUser, now, setTimeout, console }` control the stub ExtPay, the clock and timers; `getUserCalls()`, `paidListeners` and `proStatusCache()` read it (the `proStatusCache` write on service worker start is kept out of `writes` and `storage()`). `chrome.storage.local` and `chrome.storage.sync` (option `syncStorage`, where ExtPay keeps `extensionpay_user`) call `listeners.storageOnChanged` after every `set()` that changes a value, like Chrome; `bg.chrome.storage.sync.set({...})` writes like ExtPay. Open tabs and injection: options `{ tabs, scriptingError }`, read `tabsQueries` and `scriptingCalls`. Plans and checkout: options `{ getPlans, noExtPay, contexts }` (the stub ExtPay's `getPlans`, a failed ExtPay init, what `chrome.runtime.getContexts()` returns), read `getPlansCalls()`, `openPaymentPageCalls`, `tabsCreated`, `tabsUpdated`, `windowsUpdated`; `extensionUrl(path)` is what `chrome.runtime.getURL(path)` returns.

**Live** (real Chromium + this extension + real logged-out YouTube): `node tests/live/smoke.js`
Prints a JSON report, exit 0 if the content script ran. Never signs in; on consent pages it clicks only "Reject all".
Needs playwright-core and Chromium, auto-detected (override: `PLAYWRIGHT_CORE_PATH`, `CF_CHROMIUM_PATH`; `CF_HEADED=1` shows the window).
Build new scenarios on `tests/live/harness.js`: every browser call has a hard timeout; wrap whole scripts in `watchdog()`.
`h.attachContentWorld(page)` evaluates expressions inside CleanFeed's content-script world (e.g. `YT.isChannelPage()`), which `page.evaluate` cannot reach.
`node tests/live/menu.js` (about 2 min): opens real 3-dot menus on a channel page, a search page and a Shorts shelf; checks the tab stays responsive and each menu holds one correct set of CleanFeed items.
`node tests/live/navigation.js` (about 100 s): SPA navigation watch -> owner channel -> another channel (blocked) -> Home, a blocked channel -> Home, and the subscriptions toast across navigations; checks that page-level decisions read only the visible page, not YouTube's hidden cached pages. Then a channel's Videos tab: the page handle has no tab in it (`@mkbhd`, not `@mkbhd/videos`), the Block button stores it so, and a channel stored as `@mkbhd/videos` by an older version still blocks by handle.
`node tests/live/shorts.js` (about 1 min): search-result Shorts (`ytm-shorts-lockup-view-model` in `grid-shelf-view-model`) untouched with nothing blocked; with "minecraft" blocked every matching Short is hidden (one card per Short, empty shelves hidden), and the `/shorts` player hides a matching short, pauses it and resumes playback on the next shown short; a channel's Shorts tab keeps one card per grid cell.
`node tests/live/quickadd.js` (about 1.5 min): CF+ quick-add on a result with an apostrophe or hyphen in its title and on a Cyrillic one (the chip keeps the punctuation, the stored keyword equals the chip, matches the title and hides the card), then the Scan modal on a channel's Videos tab (every candidate matches a title; ticking one stores it), then the CF+ layout (`node tests/live/quickadd.js layout` runs only this, about 35 s): on a channel's Videos and Shorts tabs, search results with Shorts and a watch page's side column, CF+ never overlaps YouTube's 3-dot button, shows and takes the click on hover, and the 3-dot button keeps its own click.
`node tests/live/autotag.js` (about 1 min): category auto-tag on search results: a plain keyword ("trailer") sends and stores no auto-tag hit; a topic ("gaming") sends each video once across several full refilters, stores only videos hidden on the page (by video id) and tags exactly the channels with 3+ distinct videos; Untag in Options removes the tag, and the channel is not counted or tagged again after a reload.
`node tests/live/categories.js` (about 15 s): options.html and popup.html (which load content-dom.js) open with no console or page error; Options > Topics lists 35 topics by display name, each with exactly the terms blocking uses (no raw `ai_hype` / `true_crime`); the popup shows 35 topic chips; the topic panel of a real 3-dot menu offers "Add to category" for every blocked topic, by display name.
`node tests/live/hidden-features.js` (about 1 min): the features hidden in features.js stay hidden for a user who had them on: a saved interest and an always-off schedule exempt nothing, a used-up daily limit shows no overlay, a blocked search gets no curiosity prompt, no time-tracking write in 35 s; popup.html and options.html (English and Italian) open with no console error and no Interests / Schedule / Time-limit / Smart-Decay UI or copy.
`node tests/live/strict.js` (about 45 s): Strict Mode on for a free user (Pro lapsed): popup.html asks for the password on a weakening click (cancel or a wrong one changes nothing, "Wrong password." shown), then remembers it for that page only; options.html asks before an import that removes blocks and before Untag, and its Strict switch turns strict mode off with the password (no payment page); on YouTube the pause switch, peek switch, "Untag channel" and "Show just now" are locked ("Locked by Strict Mode" tooltip and toast) and lock/unlock live when the setting changes. Also a free user with strict mode off: importing a backup that has strict mode on keeps it off (no password hash), imports the rest and says "Strict Mode is a Pro feature and was not imported." (English and Italian).
`node tests/live/presets.js` (about 30 s): service worker start caches Pro status (`proStatusCache`); popup.html's button reads "Upgrade to Pro" with no price in English (Auto and chosen) and "Passa a Pro" in Italian, and options.html's plan picker is titled in that language; a free user with one custom keyword who clicks Focus mode (3 topics) gets nothing added, no alert and no page, but an inline notice with the real numbers and an Upgrade button (English and Italian); a preset already fully blocked applies with no notice; with nothing blocked every preset (3 topics each) applies whole with no notice, and popup.html then reads "3/3 keywords used" ("3/3 parole usate") with the other topics locked.
`node tests/live/plans.js` (about 10 s): the plan picker with the real ExtensionPay plans: options.html#upgrade (English and Italian) opens the About tab on the picker (focused, in view), with one card per plan priced as `cfBuildPlanCards` formats it, yearly highlighted, "Best value" only when allowed, the currency note and the "stay free" line (the "See plans" button when no plans load); popup.html's line under "Upgrade to Pro" is `cfPlansLine` of the same plans; a plan-less `openPaymentPage` opens options.html#upgrade, or shows the picker in an options tab that is open already (no new page); a plan's Choose button opens extensionpay.com/extension/cleanfeed/choose-plan/<nickname> (ExtPay gets a placeholder API key, so no key is created; the tab's resources are aborted and it is closed at once: no checkout ever loads).
`node tests/live/reinject.js` (about 70 s): install/update handling on a temp copy of the extension (`h.launch({ extensionDir })`, `h.reloadExtension()`, which turns on developer mode in the test profile so Chromium keeps a reloaded unpacked extension): after a reload the open YouTube tab gets a new CleanFeed instance without a page reload (new marker on `<html>`, filtering again, one set of UI and menu items, no second instance when injected twice, still filtering after an SPA navigation); then, with injection disabled in the copy, the orphaned instance stops, clears the page and shows one "CleanFeed was updated — reload this page" toast; finally, in a fresh browser, v1.3.2 (git 851fb22) runs the tab and this version is copied over it and reloaded: same checks as the update, plus one "reload this page" notice (v1.3.2 keeps running until a reload), then a video card's 3-dot menu and a Shorts shelf item's menu while v1.3.2 adds its own items to them: the tab stays responsive, v1.3.2's items are left alone and hidden, and each menu shows at most one set of CleanFeed items. `node tests/live/reinject.js upgrade` runs only the v1.3.2 part, `current` only the rest.
