# CleanFeed v1.4 — Pricing & Plan Picker Plan

**Goal:** make Pro easy and honest to buy.
- An in-app plan picker shows Monthly / Yearly / Lifetime, with real prices pulled from ExtensionPay and the yearly saving made obvious.
- Every upgrade button leads there.
- Close the remaining product-level gaps the v1.4 final review flagged.

**Decisions (from the user, 2026-10-12):**
- Pricing in USD for all languages: Monthly $2.99, Yearly $19.99, Lifetime $29.99 as a launch price until 2026-12-31 (later $39.99).
- The ExtensionPay plans are changed by the controller at publish time. **This code must not hard-code prices.** It reads them from ExtensionPay, so it stays correct before and after the dashboard change.
- Evidence and copy guidance: `research/pricing-recommendation-2026-10-12.md` (sections 2, 3, 4, 7).

**Branch:** `feat/v1.4-pricing` from `main` at `b42be12`. Never push.

## Global Constraints

1. Plain-JS Manifest V3, no build step, no new runtime dependencies. Any new file the extension loads goes in the right HTML / manifest / importScripts AND the `package.sh` whitelist. `tests/` is never packaged.
2. No untrusted data in `innerHTML` / `insertAdjacentHTML`. Use the `cfEl` helper or `textContent`.
3. New user-visible strings are English-first, with keys in BOTH `_locales/en` and `_locales/it`, read through the existing helpers (`msg()` in content.js/options.js, `cfMsg()` in popup.js). A literal `$` before a digit is written `$$`.
4. **No hard-coded prices in shipped code or `_locales`.**
   - Prices, currency and intervals come from ExtensionPay `getPlans()` (fields: `unitAmountCents`, `currency`, `interval` = `month` | `year` | `once` (lifetime), `nickname`).
   - When plans can't be loaded, show no numbers. A plain "See plans" button opens ExtensionPay's own page.
   - `docs/store-listing.md` may state the configured prices.
5. **Honest copy.**
   - "Best value" appears only when the yearly per-month price is lower than the monthly price.
   - Never "Most popular".
   - The lifetime launch note ("Launch price until Dec 31, 2026") is date-gated: shown only on or before 2026-12-31 (local date).
   - Round the yearly per-month price UP to the cent, and the saving % DOWN.
   - Currency shown as Intl formats it for the UI language (en: "$2.99"; it: "2,99 USD"), plus a short "Prices in USD" note when the currency isn't the UI's natural one. Italian note: "Prezzi in USD; la tua banca converte in euro".
6. Stay in scope; follow the existing style; existing users' data keeps working.
7. Verify every task:
   - `node --check` on modified `.js` files;
   - unit tests in `tests/unit/` run by `node tests/run-unit.js` (must exit 0);
   - the live harness `tests/live/` where the task says so;
   - commands and output in your report.
8. Commit per task with a conventional message ending in `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
9. Do not modify `lib/ExtPay.js`.

### Task 1: Plan picker, upgrade routing, price copy

**Build:**

1. **Background — plans.**
   - New message `getPlans`. It returns ExtensionPay `getPlans()` normalized to `[{ nickname, interval, unitAmountCents, currency }]`.
   - Cache the result in `chrome.storage.local` (`plansCache`, `{ plans, fetchedAt }`) with a 24 h TTL: serve a fresh cache directly; refresh a stale one in the background; on failure return the last cache, or `{ plans: [] }`.
   - Plans with `unitAmountCents` missing or 0 are dropped.

2. **Background — opening checkout.**
   - The `openPaymentPage` handler accepts an optional `plan` (nickname).
   - With `plan`: call `extpay.openPaymentPage(plan)`.
   - Without `plan`: open the in-app picker, `chrome.runtime.getURL('options.html#upgrade')`. Focus an existing options tab instead of opening duplicates if practical.
   - Keep the existing fallback when ExtPay isn't available.

3. **Pure helper `cfBuildPlanCards(plans, uiLang, today)`** in `content-dom.js` (unit-loadable; already loaded by popup/options). It returns view-models for Monthly / Yearly / Lifetime (each only if its plan exists):
   - the formatted price via `Intl.NumberFormat` for `uiLang`;
   - for yearly: per-month price (rounded up) and saving % vs monthly (rounded down; only if a monthly plan exists and the saving is > 0);
   - `bestValue` true on yearly only when its per-month price is lower than monthly;
   - `launchNote` true on lifetime only when `today <= 2026-12-31`.

   Monthly and yearly are matched by `interval` (`month` / `year`); lifetime by `interval === 'once'`. If several plans share an interval, prefer the nickname `monthly` / `yearly` / `lifetime`.

4. **Options page — picker** (`options.html` + `options.js` + `styles/options.css`):
   - Replace the current single upgrade card with a "Choose your plan" section (`id="upgrade"`) of up to three cards: Monthly, Yearly (preselected / visually highlighted, "Best value" badge when allowed), Lifetime.
   - Each card has its own button that sends `{ action: 'openPaymentPage', plan: <nickname> }`.
   - Under the cards: the Pro feature line (`upgradeProDesc`), the currency note, and "Channel blocking and hiding Shorts & comments stay free."
   - When no plans are available: one "See plans" button (`openPaymentPage` with no plan → ExtensionPay page directly).
     - Careful: the background now routes plan-less calls to the picker. Use a distinct flag, e.g. `{ action: 'openPaymentPage', direct: true }`, which calls `extpay.openPaymentPage()`.
   - Opening `options.html#upgrade` scrolls to and visually focuses the section.
   - Pro users see a short "You're Pro — thank you" state instead of prices.
   - Every other upgrade button in options routes to `#upgrade`.

5. **Popup:**
   - The Upgrade button text becomes "Upgrade to Pro" (no price).
   - The line under it is computed from cached plans, e.g. "$1.67/mo billed yearly · or $2.99 monthly" (it: "1,67 USD/mese con l'annuale · o 2,99 USD al mese"), or nothing if plans are unavailable.
   - Clicking opens the picker (plan-less `openPaymentPage`).

6. **Content-script CTAs** (cap reached, subscription toast, etc.) keep sending plan-less `openPaymentPage`, so they now land on the picker. Check that each one still makes sense.

7. **Locales:**
   - Remove the price from `upgradeToPro` in both locales (fixes the wrong "€" in Italian).
   - Add the new strings: plan names, per-month/billed-yearly/save patterns with substitutions, the one-time note, the launch note, the currency notes, the "stay free" reassurance, the See-plans fallback and the You're-Pro state.

8. **Docs:** update the price lines in `docs/store-listing.md` (EN and IT) to: Monthly $2.99, Yearly $19.99 (= $1.67/mo, save 44%), Lifetime $29.99 launch price until Dec 31, 2026.
