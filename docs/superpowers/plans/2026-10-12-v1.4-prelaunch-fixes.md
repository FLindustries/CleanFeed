### Task 1: Correct channel IDs from card links, and the English "Most relevant" label

**Problem 1 (bug).** `YT.getChannelId(card)` in `content-dom.js` uses `/\/(channel|c|user|@)([^\/\?]+)/` and returns the wrong value for several link shapes:
- `/channel/UCxxxx` → `"hannel"` (the alternation backtracks to `c` + `hannel`);
- `/c/Name` and `/user/Name` → null.

Consequences:
- Blocking a channel from such a card stores the id `"hannel"`. `cfChannelHandle` then turns it into `@hannel`.
- The real channel is never matched by handle.
- Every handle-based rule (CSS pre-hide, handle sweep, /shorts handle match, peek keys) targets `@hannel` instead. That can hide unrelated channels whose handle starts with "hannel" and miss the blocked one.

**Required:**
- `getChannelId` returns a value `cfChannelHandle` turns into the correct `@handle` for `/@handle` links, with the same output format the code already produces for those links.
- For `/channel/`, `/c/` and `/user/` links it returns null. Name-based matching still applies, and no garbage handle is ever produced.
- Check `getPageChannelId` and every other place that derives a handle from a URL or href, and make them consistent: a non-@ path must never become an `@handle`.
- Read old data defensively. A stored blocked-channel id that is exactly `"hannel"` (or any id produced from a non-@ path) must not become a handle rule. Ignore it for handle matching and keep the entry (its name still blocks).
- Unit tests:
  - `/@mkbhd`, `/@MKBHD/videos`, `/channel/UCBJycsmduvYEL83R_U4JriQ`, `/c/Veritasium`, `/user/marquesbrownlee`, links with query strings;
  - a stored `{ name, id: 'hannel' }` produces no `@hannel` handle rule.

**Problem 2 (copy).** The English UI calls the Subscriptions shelf toggle 'Hide "More relevant"', but YouTube's English label, and what the code detects, is "Most relevant".
- Change the English user-facing strings that name this shelf to "Most relevant" (keep the Italian "Più pertinenti").
- Update any test that asserts the old string.
- Check `docs/store-listing.md`: if it names the toggle, keep it consistent.
