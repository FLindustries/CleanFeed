### Task 1: Correct channel IDs from card links, and the English "Most relevant" label

**Problem 1 (bug).** `YT.getChannelId(card)` in `content-dom.js` uses `/\/(channel|c|user|@)([^\/\?]+)/` and returns the wrong value for several link shapes:
- `/channel/UCxxxx` → `"hannel"` (the alternation backtracks to `c` + `hannel`);
- `/c/Name` and `/user/Name` → null.

Consequences:
- Blocking a channel from such a card stores the id `"hannel"`. `cfChannelHandle` then turns it into `@hannel`.
- The real channel is never matched by handle.
- Every handle-based rule (CSS pre-hide, handle sweep, /shorts handle match, peek keys) targets `@hannel` instead. That can hide unrelated channels whose handle starts with "hannel" and miss the blocked one.

**Required:**
- `getChannelId` returns a value `cfChannelHandle` turns into the correct `@handle` for `/@handle` links, with the same output format the code already produces for those links.
- For `/channel/`, `/c/` and `/user/` links it returns null. Name-based matching still applies, and no garbage handle is ever produced.
- Check `getPageChannelId` and every other place that derives a handle from a URL or href, and make them consistent: a non-@ path must never become an `@handle`.
- Read old data defensively. A stored blocked-channel id that is exactly `"hannel"` (or any id produced from a non-@ path) must not become a handle rule. Ignore it for handle matching and keep the entry (its name still blocks).
- Unit tests:
  - `/@mkbhd`, `/@MKBHD/videos`, `/channel/UCBJycsmduvYEL83R_U4JriQ`, `/c/Veritasium`, `/user/marquesbrownlee`, links with query strings;
  - a stored `{ name, id: 'hannel' }` produces no `@hannel` handle rule.

**Problem 2 (copy).** The English UI calls the Subscriptions shelf toggle 'Hide "More relevant"', but YouTube's English label, and what the code detects, is "Most relevant".
- Change the English user-facing strings that name this shelf to "Most relevant" (keep the Italian "Più pertinenti").
- Update any test that asserts the old string.
- Check `docs/store-listing.md`: if it names the toggle, keep it consistent.

**Verify:**
- `node --check content-dom.js content.js` and the other changed files;
- `node tests/run-unit.js` exits 0;
- live `node tests/live/smoke.js` and `node tests/live/navigation.js` still pass.

### Task 2: No view counts as channel names; standard zip paths

**Problem 1 (bug, seen live).**
- On a channel's Videos tab (e.g. `https://www.youtube.com/@mkbhd/videos`), the 3-dot "Block channel permanently" item gets `data-cf-channel="6.8M"`. The card shows no channel name, so the code takes a view/subscriber count instead.
- `isValidChannelName` accepts strings like "6.8M" or "6,5 Mln".
- Clicking the item would block a channel named "6.8M" and show "Blocked '6.8M' permanently".

**Required:**
- `isValidChannelName` rejects count-like strings in common UI languages:
  - a number with an optional decimal and a K/M/B suffix or localized words ("6.8M", "1,2 Mln", "3 mila", "1.2K views", "views", "visualizzazioni", "subscribers", "iscritti");
  - pure numbers;
  - date-like strings ("2 days ago", "2 giorni fa").
- Real names must still be accepted: "Il Sole 24 Ore", "MrBeast", "TED", "Vsauce3", "4K Media", "1MILLIONTHINGS", and non-Latin names. Write the tests first, cover these cases, and keep the existing isValidChannelName tests passing.
- When a card has no valid channel name and the page is a channel page (`YT.isChannelPage()` on the active page), the 3-dot block item uses that page's channel (`YT.getPageChannelName()` / `getPageChannelId()`).
- If no valid name is found anywhere, no "Block channel" item is added (the topic item still is).

**Problem 2 (packaging).**
- `package.sh` uses PowerShell `Compress-Archive`, which writes zip entry names with backslashes.
- Build the zip with forward-slash entry names instead: Python's zipfile is available (`python -I -c ...`), or another tool already on the machine. Keep the same whitelist and output name.
- Print the size with a dot decimal.
- Verify by listing the entries.

**Verify:**

- `node tests/run-unit.js` exits 0;
- live `node tests/live/menu.js`: on the @mkbhd Videos tab, the block item's channel is "Marques Brownlee" or the page's channel, never a count;
- `bash package.sh` and list the zip entries (forward slashes, no tests/).
